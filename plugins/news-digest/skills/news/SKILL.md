# ニュースまとめレポートの作成

見出しで候補を絞り、選んだ記事だけ本文を読んで要約する。

守ること:

- ネットワークアクセスは、収集スクリプトと本文取得スクリプトの実行だけ。RSS やページを自分で直接取得しない
- 要約は、取得した本文と見出しに書かれていることだけで書く。本文が取れなかった記事について、学習した知識から固有名詞や規格名、数値を補わない
- 一時ファイルを作らない。生成してよいのは作業フォルダ内の items.txt とレポートだけ
- 既存のレポートファイルを上書き・編集しない。形式を変えてほしいと言われたときも過去のレポートには手を入れず、設定を変えて次回以降に反映する。今の内容で新しい形式を見たい場合は、収集からやり直さず items.txt から別ファイル(末尾に `-2` など)として作る

## 設定

作業フォルダは `~/news-reports`。この中に設定ファイルを置く。

- `preferences.md`: 件数・絞り方・レポート形式・既定キーワード
- `sources.txt`: 情報源の URL(1行1つ。`{KEYWORD}` はキーワードに置き換わる。`#` 始まりと空行は無視)
- `seen.txt`: 収集スクリプトが自動で作る既読記録(手で編集しない)。これにより毎回「前回以降の新着」だけが集まる。すべての記事をもう一度見たいときは削除する

## 手順

1. `~/news-reports` が無ければ作成する
2. `preferences.md` が無ければ、レポートを作る前にユーザーに希望を質問し、`preferences.md` と `sources.txt` を作る。質問する項目:
   - **読み手のこと**: 仕事や役割、扱っている分野、いま気にしていること。記事を選ぶときと、読み手にとっての意味を書くときに使う。答えたくない場合は指定なしでよい(その場合は一般的な書き方になる)
   - **追いかける言葉**: 既定にするキーワード(例: 生成AI)
   - **件数**: 何件にまとめるか(既定は「今日読むべき3件」。10件や、重要なものは全部、なども可)
   - **情報源**: 既定は下記の10本(国内6・海外4)。増やすか減らすかを聞く。判断の目安も伝える
     - 増やすとよい人: 業界の動きを幅広く押さえたい、海外の一次情報も追いたい、担当分野が複数ある。ただし収集と要約に時間がかかり、Claude の利用量も増える
     - 減らすとよい人: 決まったメディアだけ読めばよい、毎朝短時間で済ませたい、特定の分野に絞りたい
     - 自分の業界紙や専門メディアの RSS を足すと、レポートの精度が上がる
   - **絞り方**: 重要度順、キーワードとの関連度順、など
   - **レポート形式**: 既定の構成(下記)でよいか、変えたいか
   既定の `sources.txt` は次のとおり。上2つはキーワードで検索し、それ以外は各サイトの新着を集める。
   ```
   # キーワードで検索する情報源
   https://news.google.com/rss/search?q={KEYWORD}&hl=ja&gl=JP&ceid=JP:ja
   https://b.hatena.ne.jp/q/{KEYWORD}?mode=rss&target=text
   # 業務での使い方・導入事例
   https://note.com/hashtag/AI%E6%B4%BB%E7%94%A8/rss
   https://ainow.ai/feed/
   # 国内のニュースサイト
   https://rss.itmedia.co.jp/rss/2.0/aiplus.xml
   https://rss.itmedia.co.jp/rss/2.0/news_bursts.xml
   https://www.publickey1.jp/atom.xml
   https://feeds.japan.cnet.com/rss/cnet/all.rdf
   # 海外のニュースサイト
   https://techcrunch.com/category/artificial-intelligence/feed/
   https://arstechnica.com/ai/feed/
   https://www.technologyreview.com/topic/artificial-intelligence/feed
   ```
   情報源には性質の違いがある。ユーザーが情報源を選ぶときは、この違いも伝える。
   - Googleニュースとはてなブックマークは、キーワードで幅広く拾える代わりに、広告記事や無関係な記事が混じることがある
   - 各ニュースサイトの新着は、編集されているためノイズが少ない代わりに、そのサイトが扱う範囲に限られる

   ユーザーの立場に応じて、次のような足し方も提案する。
   - 業務で AI を使う立場: 既定の note と AINOW が該当する。物足りなければ ASCII.jp `https://ascii.jp/rss.xml` を足す
   - 開発者: Zenn の AI トピック `https://zenn.dev/topics/ai/feed`、Hacker News `https://hnrss.org/newest?q={KEYWORD}&points=50`(英語のキーワードのときだけ使える)
   - 経営・企画: 情報源を足すより、キーワードを「AI 導入事例」「生成AI 業務効率化」のように業務寄りにするほうが効く
   - 製造業・半導体を追う人: EE Times Japan `https://rss.itmedia.co.jp/rss/2.0/eetimes.xml`、MONOist `https://rss.itmedia.co.jp/rss/2.0/monoist.xml`
   - 研究・調査: arXiv `http://export.arxiv.org/rss/cs.AI`(件数が多いので絞り方の指定を勧める)
3. OS に合わせて収集スクリプトを、`~/news-reports` をカレントディレクトリにして実行する。キーワードは、ユーザーの指定があればそれを、なければ `preferences.md` の既定キーワードを引数で渡す
   - macOS: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/collect.sh" "<キーワード>"`
   - Windows: `powershell -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/scripts/collect.ps1" -Keyword "<キーワード>"`
4. `~/news-reports/items.txt` を読む。前回以降の新着だけが入っている。キーワードと関連の薄い記事を除き、`preferences.md` の件数と絞り方に従って、レポートに載せる候補を選ぶ。preferences.md に読み手のことが書かれていれば、その人にとって意味があるかを優先の基準にする。新着が1件も無ければ、レポートは作らず「前回以降の新着はありません」と伝えて終える
5. 選んだ記事の本文を取得する。**選んだ記事すべてについて1件ずつ必ず実行する**。Googleニュースの転送リンクも、スクリプトが元記事を調べて本文を取る
   - macOS: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/fetch.sh" "<URL>"`
   - Windows: `powershell -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/scripts/fetch.ps1" -Url "<URL>"`
   「本文を取得できませんでした」「転送リンクのため本文を取得できません」と返った記事は、見出しだけで書く
6. レポートを `~/news-reports/<取得日時>.md` に新規作成する。`<取得日時>` は items.txt の1行目の取得日時を `YYYY-MM-DD_HHMM` にしたもの(例: `2026-08-14_0730.md`)。同名があれば末尾に `-2`、`-3` を付ける
7. レポートの既定の構成。preferences.md に指定があればそちらに従う
   - 冒頭に選定基準を1行
   - 「今日のニュース<件数>件」: 見出し / 記事の要約(2文) / 元記事へのリンク
   - **使う記法は、見出し・太字・箇条書き・リンクだけにする**。表、水平線(`---`)、コードブロック、画像、引用は使わない。見出しの番号は `（1）` のように全角の丸括弧で書き、`1.` の形は使わない。URL は `[媒体名](URL)` の形で書き、そのまま置かない
     Windows のメモ帳はこれら以外の記法に対応しておらず、開いたときに警告が出るため
   - **英語の記事は、見出しも要約も日本語で書く。見出しの後ろに原題を丸かっこで添える**
   - **本文取得スクリプトが「本文なし」と返した記事は、見出しの末尾に「(見出しのみ)」と付ける。この印は必ず付ける**
   - 最後に残りの記事を `- [タイトル](URL)` の箇条書きで(英語のタイトルは日本語訳を添える)
   既定は要約までにとどめる。読み手にとっての意味づけ(注目すべき理由、自分への影響など)は、ユーザーが求めたときに preferences.md へ足す
8. 完成したら選んだ記事の部分をチャットにも表示し、レポートの保存場所を伝える

## 設定を変えたいと言われたら

設定ファイルだけを書き換える。プラグイン本体(このファイルを含む)は書き換えない。プラグインを入れ直すと元に戻ってしまうため。

- 件数・絞り方・レポートの構成や欄・既定キーワードの変更 → `preferences.md` を書き換える
- 情報源の追加・削除 → `sources.txt` を書き換える(追加はその RSS の URL を1行足す)

よく頼まれる欄の追加。指示があったときだけ足す。
- 「注目すべき理由」: なぜその記事が注目に値するかを2文で。記事の内容と、それが何を変えるのかを書く
- 「自分への影響」: preferences.md に書かれた読み手の仕事や関心に照らして、その人の判断や作業にどう関わるかを1文で。読み手のことが書かれていない場合は、一般的な書き方にとどめ、具体的な職種を想像して書かない
- 「朝会で使える一言」: そのまま口に出して読める話し言葉で1〜2文

変更したら、次回の実行から反映されることを伝える。元に戻したいと言われたら、変更前の記述に戻す(同じ会話の中でのみ戻せる)。
